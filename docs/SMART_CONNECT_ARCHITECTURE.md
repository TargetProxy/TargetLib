# Smart Connect 架构目标与路线图

## 目标

TargetLib 的 Smart Connect 将运行时模型从：

```text
active subscription -> proxy selector -> 当前节点
```

升级为：

```text
多个订阅 -> 统一节点池 -> 多个服务 selector -> 域名级路由 -> 独立服务绑定
```

核心目标：

- 多个订阅独立更新，并合并为带来源信息的统一节点池；
- 节点拥有稳定身份，节点质量与绑定关系可跨更新保留；
- 每个服务拥有独立 selector、域名路由和当前绑定；
- 服务绑定、selector 选择和探测结果由核心持久化并可查询；
- 配置应用有明确阶段、revision 和失败原因，失败时保留当前生效配置；
- 候选评估与运行时故障转移分离，核心不自动 fallback；
- 通过运行时事件让客户端确认配置和绑定确实已生效。

## 边界

`subscriptions` 负责订阅与节点池，`profile` 负责节点规范化，`config.Build` 负责由设置、节点池和服务路由生成配置，`manager` 负责事务化应用与生命周期。gRPC 只暴露这些能力；平台相关能力由宿主实现。供应商原始配置不透传。

## 路线图

### P0：运行时骨架

1. 定义统一节点池和稳定 `node_id`，保留 `subscription_id` 与声明地区。
2. 将配置输入从 active subscription 改为节点池、selector 定义和服务路由。
3. 支持多个 selector，共享节点 outbound，同时独立保存选择状态。
4. 增加服务绑定模型、持久化和查询/应用/移除 API。
5. 明确配置应用事务：`VALIDATING -> BUILDING -> APPLYING -> READY/FAILED`，失败保留旧配置。
6. 提供运行时状态查询，确认 selector、路由和绑定的实际生效状态。

### P1：可用体验

1. 增加服务级探测：DNS、TCP、TLS、HTTP、认证、超时和地区不符合等失败阶段。
2. 增加实际出口地区检测，区分声明地区、观测地区和服务地区。
3. 存储基础节点质量与服务质量历史，支持绑定有效期和重新评估。
4. 增加 `RuntimeEvent` 流，发布配置、selector、绑定和探测状态变化。
5. 将订阅更新与运行配置解耦：只标记受影响绑定待评估，不自动切换出口。

### P2：增强能力

加入丢包率、区域解锁检测、统一节点评分、诊断报告、质量趋势和多设备同步策略。

## 交付原则

- 先扩展领域模型和持久化，再扩展 `config.Build`，最后补齐 gRPC 与客户端状态流。
- 所有自动选择只产生候选评估结果；应用绑定必须是显式操作。
- 每个阶段保持旧单 selector API 可兼容迁移，直到新模型覆盖现有调用方。
